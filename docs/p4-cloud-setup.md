## 2. 部署云函数

1. 在微信开发者工具中同步云函数列表。
2. 新建时优先选择 Node.js 18.15；若存量函数不能切换，保留 Node.js 16.13，并把超时设置为至少60秒。
3. 上传 `miniprogram/cloudfunctions/careerAssistant`，选择“云端安装依赖”。
4. 更新既有 `userCenter`。P4增加了“已有已确认简历”会话状态、有效额度预留计算和个人数据级联删除。

如果命令行首次部署只创建了函数，并在函数信息中显示 `Nodejs16.13 / 3秒`，先把超时调整为 `60秒`，保存并等待状态恢复为 `Active`，再上传代码。部分存量函数无法原地切换运行时；当前实现兼容 `Nodejs16.13` 到 `Nodejs18.x`，无需删除函数或创建新版本。

部署目录中不应保存 `node_modules`；`careerAssistant` 只依赖项目已经使用的 `wx-server-sdk 4.0.2`，模型请求使用 Node.js 原生 HTTPS，避免绑定特定云函数运行时。

## 3. 配置环境变量

仅在 `careerAssistant` 云函数的环境变量中设置：

```text
DEEPSEEK_API_KEY=<在DeepSeek控制台创建的密钥>
DEEPSEEK_MODEL=deepseek-v4-pro
```

模型也可显式设为 `deepseek-flash`。代码拒绝其他模型ID，避免配置拼写错误后静默调用未知模型。

## 4. 验收顺序

1. 打开首页，已保存过简历时主按钮应显示“开始岗位方向分析”。
2. 意向方向留空或输入不超过60字，选择中文、英文或双语。
3. 完成12题，或点击“跳过问卷”。
4. 分析应返回恰好3个方向；每项显示程序计算分数和逐字来自确认简历的证据。
5. 选择1至3个方向生成；成功后每日额度减少1，而不是按方向数量减少。
6. 模型超时、格式错误或事实越界时不保存生成版本，并释放预留额度。
7. 核对页显示各段事实编号和打招呼语；联系方式仅在服务端重新合并。
8. 在历史页执行“清空全部个人数据”时，P4五个集合中的当前用户记录也应删除。

## 5. 常见错误

- `MODEL_NOT_CONFIGURED`：云函数未设置 `DEEPSEEK_API_KEY`，或模型ID不是允许值。
- `CONFIRMED_RESUME_REQUIRED`：当前用户尚未完成P3事实确认。
- `DAILY_QUOTA_EXCEEDED`：当天已使用或正在处理的完整生成任务达到3次。
- `MODEL_TIMEOUT`：岗位分析在单次48秒截止内未完成，或简历生成在单次50秒截止内未完成。
- `MODEL_OUTPUT_INVALID`：结构化输出、事实编号、逐字证据或数字校验失败；不会保存或扣除完整额度。生成Schema会把岗位ID、事实ID、语言和方向数量限定为本次请求的允许值。
